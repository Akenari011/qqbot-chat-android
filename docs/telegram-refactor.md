# Telegram 风格聊天重构

本轮沿用 Kotlin / Compose 与现有 QQ Bot API，改善日常聊天界面与状态可靠性。保留原有会话 JSON 格式，并以可选字段兼容旧记录；没有加入新的运行时框架或替换后台协议。

## 用户可见变化

- 会话页增加侧边抽屉、分类、归档入口、草稿预览及历史搜索；只剩归档会话时仍可进入。
- 聊天页增加连续消息分组、日期分隔、滑动回复、引用跳转、表情面板、附件分类与回到最新消息。读旧消息时收到消息不会强制跳到底部。
- 草稿和引用属于各自会话。转发文本先选择接收方再确认，避免发到任意另一个会话。
- 图片可以全屏缩放与拖动；发送图片显示本地预览。读取附件移到 IO 线程，限制为 20 MB，录音支持取消并在应用离开前台时停止。
- 浅色 / 深色、蓝色气泡、字体缩放与外观预览可用。界面采用已有 Telegram 风格色值和气泡几何，不新增 Telegram 源码。
- 页面使用 240 ms 短距离转场，局部内容使用 180 ms 过渡；滑动回复使用可打断的弹簧返回。面板完成退场后才打开下一步操作。

## 数据与发送修复

- 会话列表发出独立快照，避免原地修改数据导致 StateFlow 不刷新。
- 网络任务捕获原始会话与登录会话版本，用户切换聊天后不会把发送结果写进当前聊天。
- 本地消息 ID 与服务器 ID 分开保存，发送重试复用同一行；引用、去重、撤回使用服务器 ID。撤回失败保留原消息。
- 被动回复序号在发送前原子分配。没有被动回复来源的群聊 / 私聊会提示原因。
- 串行合并持久化写入，使用 Android AtomicFile，写入失败保留旧文件并提示。
- 演示数据在独立内存中运行，不覆盖真实会话；恢复的旧 JSON 缺少新字段时保持默认值。

## 真实机器人验收清单

以下需要维护者自己的测试机器人、QQ 用户和权限，本轮未执行：

1. 使用有效凭证连接；私聊和群聊先收到用户消息，再发送文本与引用，切换会话后核对发送落点。
2. 上传图片、视频、音频和文件，检查服务器支持的类型及大小；确认本地图片预览、权限拒绝和网络失败提示。
3. 发送中断网、重连后重试文本；确认服务器 ID 撤回，撤回权限或时限失败时内容保留。
4. 在有权限的频道读取列表、历史、置顶及日程，添加表情回应，检查未授权时的错误提示。
5. 打开系统键盘后切换表情、开始录音后切到后台、在图片预览中缩放；用物理设备检查手势与无障碍读屏。

## 明确的边界

QQ Bot API 的权限、被动回复窗口和消息类型限制仍然适用。通话、秘密聊天、多端历史同步及后台推送需要额外服务端或系统集成，本轮没有实现。媒体转发、附件自动重传、崩溃后自动恢复发送、搜索/表情面板的预测返回预览也未实现。持久化仍为单个 JSON 文件，适合当前规模；大量历史的分页数据库迁移应作为独立改动。

推荐先用测试机器人完成上述验收再发布。继续沿用现有 Compose 与 QQ 接口，能够减少维护成本；若后续需要通话或多端同步，应先确定新的服务端方案，再讨论界面入口。
